# Phase DASH-15 — UI Design Contract

> Visual and interaction contract for the L-level badge column + per-rung drawer added to the Coverage Matrix route.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Scope note:** This phase adds exactly two new UI surfaces to the existing `/coverage` route:
> 1. A `LevelBadgeCell` column (new `<td>` between `claudeMd` and `gitNexus`)
> 2. A `ClaudeMdLevelDrawer` modal (native `<dialog>`, opened by clicking the badge cell)
>
> All foundational design-system decisions (palette, typography scale, spacing unit, component library)
> are inherited from the shipped Phase 05.1 token set. This spec records only what is NEW or
> PHASE-SPECIFIC. The executor MUST NOT introduce parallel design language.

### L-level Badge Color Mapping

Each L-level maps to an existing semantic token pair (background + text). This is the exhaustive, locked mapping — the executor must use exactly these tokens:

| Level | Pill Background | Pill Text | Rationale |
|-------|----------------|-----------|-----------|
| L0 (Absent) | `bg-text-tertiary/10` | `text-text-tertiary` | Muted — nothing present; matches `not-applicable` cell state |
| L1 (Basic) | `bg-status-warning/10` | `text-status-warning` | Amber — file exists but minimal; "something there, not yet rich" |
| L2 (Scoped) | `bg-status-warning/10` | `text-status-warning` | Amber — progressing |
| L3 (Structured) | `bg-status-info/10` | `text-status-info` | Blue — meaningful structure established |
| L4 (Abstracted) | `bg-status-info/10` | `text-status-info` | Blue — path-scoped rules present |
| L5 (Maintained) | `bg-status-success/10` | `text-status-success` | Green — active maintenance signals |
| L6 (Adaptive) | `bg-status-success/10` | `text-status-success` | Green — full adaptive tooling |
| Degraded | `bg-text-tertiary/10` | `text-text-tertiary` | Same as `not-applicable` — scanner failed |

**Contrast guarantee:** All token pairs already used in `CoverageCell.tsx` `STATE_TOKEN_MAP` — contrast ratios are pre-validated by the existing `verify-contrast.test.ts` invariant.

**Inferred-L5 marker color:** When `eval.inferred === true`, the badge receives an additional "inferred" affix styled with `bg-accent-bg text-accent` — the accent-light pair — so it reads as "flagged information, not a warning." This is the ONLY use of accent in badge rendering.

## Component Specifications

### 1. `LevelBadgeCell` — the badge `<td>`

**File:** `packages/spa/src/components/panels/coverage/LevelBadgeCell.tsx`

**Column key:** `level` — insert after `claudeMd`, before `gitNexus` in `COVERAGE_COL_WIDTHS`.
```typescript
level: 'w-20',  // 80px
```

**Column header tooltip** (add to `coverageColumnTooltips.ts`):
```
'CLAUDE.md capability level (L0–L6). Click for rung details.'
```

**Props:**
```typescript
interface LevelBadgeCellProps {
  evalData: ClaudeMdEval | undefined  // undefined = pre-DASH-15 daemon / scanner degraded
  repoName: string                    // for aria-label
  onClick: () => void                 // triggers drawer open
}
```

**Visual structure inside the `<td>`:**
- The cell renders a single `<button type="button">` (not a plain `<div>`) — the badge must be keyboard-activatable since it is the drawer trigger.
- Inside the button: a pill with level label + optional inferred affix.
- The button gets `aria-label="CLAUDE.md level for {repoName}: {levelLabel}. Click for details."`.

**Badge pill anatomy:**

```
[ L4 ]           — normal (not inferred)
[ L4 ~ ]         — headline contributed by inferred L5 (see Inferred-L5 treatment below)
[  —  ]          — undefined eval (pre-DASH-15 daemon or degraded)
```

- Label text: `"L{level}"` e.g. `"L4"`. Font: `text-xs font-semibold`.
- Size: `px-2 py-1 rounded-md` — matches existing `Pill.tsx` geometry exactly.
- Colors: from the L-level color mapping table above.
- The `<button>` wrapping the pill: `w-full h-full flex items-center justify-center focus:outline-none focus-visible:ring-2 focus-visible:ring-accent rounded-md`.

**Degraded / undefined state:**
When `evalData === undefined` (scanner failed or pre-DASH-15 daemon), render:
```html
<span class="text-text-tertiary text-xs">—</span>
```
No button; no click handler (there is nothing to display in the drawer). This exactly mirrors the `row.understand` undefined fallback in `CoverageRow.tsx:214–216`.

**ARIA annotation for degraded:**
```
aria-label="CLAUDE.md level for {repoName}: not available"
```

**`<td>` className:** `${COVERAGE_COL_WIDTHS.level} px-2 py-2` — identical padding to all other data columns in `CoverageRow.tsx`.

### 2. Inferred-L5 Marker

**Rule: the inferred marker MUST NEVER be hidden.** It is not a tooltip. It is always-visible inline text. This rule applies in both the badge and the drawer.

**In `LevelBadgeCell`:**
When `eval.inferred === true`, append an inline `<span>` INSIDE the badge pill:
```html
<span class="ml-1 text-[10px] font-semibold bg-accent-bg text-accent rounded px-1">~</span>
```
The `~` glyph is the "inferred" sigil. It must appear in the rendered DOM at all times when `eval.inferred === true` — not only on hover. `aria-label` on the `<button>` includes the word "inferred" when this condition holds:
```
"CLAUDE.md level for {repoName}: L5, inferred. Click for details."
```

**In `ClaudeMdLevelDrawer` (L5 rung row):**
When the L5 rung entry has `rung.inferred === true`, add directly after the rung name:
```html
<span class="ml-1 text-[10px] font-semibold bg-accent-bg text-accent rounded px-1" aria-label="inferred">~</span>
```
Additionally, directly below the L5 rung row, show an always-visible callout:
```html
<p class="mt-1 text-xs text-text-secondary pl-6">
  Inferred — not hard-verified. Based on CLAUDE.md freshness and backbone-doc presence.
</p>
```
This callout is NOT collapsible. It renders whenever the L5 rung is present in the drawer.

### 3. `ClaudeMdLevelDrawer` — the per-rung drawer

**File:** `packages/spa/src/components/panels/coverage/ClaudeMdLevelDrawer.tsx`

**Pattern:** Native `<dialog>` via `dialogRef.current.showModal()` — exact clone of `RegisterModal.tsx` focus management. No Radix, no shadcn Sheet, no custom CSS slide animations.

**Props:**
```typescript
interface ClaudeMdLevelDrawerProps {
  isOpen: boolean
  onClose: () => void
  repoName: string
  evalData: ClaudeMdEval  // always defined when drawer is open (badge click disabled when undefined)
}
```

**Trigger:** The badge `<button>` inside `LevelBadgeCell` calls `onClick` which sets local state `drawerOpen = true` in the owning `CoverageRow`. `CoverageRow` renders `<ClaudeMdLevelDrawer>` inline (local state approach from RESEARCH §SPA Drawer).

**Focus management (exact RegisterModal pattern):**
```typescript
const dialogRef = useRef<HTMLDialogElement>(null)
const previouslyFocused = useRef<HTMLElement | null>(null)

useEffect(() => {
  const dialog = dialogRef.current
  if (!dialog) return
  if (isOpen) {
    previouslyFocused.current = document.activeElement as HTMLElement | null
    if (!dialog.open) dialog.showModal()
  } else {
    if (dialog.open) dialog.close()
    previouslyFocused.current?.focus()
  }
}, [isOpen])
```

**Keyboard:** Esc closes the drawer via `onCancel` (native `<dialog>` behavior). Wire:
```typescript
<dialog ... onCancel={(e) => { e.preventDefault(); onClose() }}>
```

**Backdrop click closes:**
```typescript
function handleBackdropClick(e: React.MouseEvent<HTMLDialogElement>) {
  if (e.target === dialogRef.current) onClose()
}
```

**`<dialog>` className (matches RegisterModal geometry):**
```
bg-card-bg border border-border-subtle rounded-lg p-0 max-w-lg w-full mx-4
dark:shadow-none shadow-card backdrop:bg-text-primary/50
```

**Internal layout (`<div class="p-6">`):**

**Section A — Header:**
```
<div class="flex items-start justify-between mb-4">
  <div>
    <h2 class="text-xl font-semibold leading-snug text-text-primary">
      {repoName}
    </h2>
    <p class="text-sm text-text-secondary mt-1">
      CLAUDE.md capability level
    </p>
  </div>
  <!-- Headline level badge (large, not a button — decorative) -->
  <span class="inline-flex items-center rounded-md px-3 py-1 text-sm font-semibold {levelTokens.bg} {levelTokens.text}">
    L{evalData.level} — {evalData.levelLabel}
    {evalData.inferred && <span class="ml-1 text-[10px] font-semibold bg-accent-bg text-accent rounded px-1">~</span>}
  </span>
  <!-- Dismiss button -->
  <button type="button" aria-label="Close capability level drawer" onClick={onClose}
    class="ml-2 h-8 w-8 flex items-center justify-center rounded-md text-text-secondary
           hover:bg-card-bg-hover hover:text-text-primary focus:outline-none focus-visible:ring-2 focus-visible:ring-accent">
    ×
  </button>
</div>
```

**Section B — Rung list (L1–L6, in order):**
```
<ul role="list" class="space-y-3 mb-6">
  {evalData.rungs.map(rung => (
    <li key={rung.rung} class="flex flex-col gap-1">
      <!-- Row: icon + rung name + inferred sigil -->
      <div class="flex items-center gap-2">
        {rung.passed
          ? <Check size={14} class="text-status-success flex-shrink-0" aria-hidden="true" />
          : <Circle size={14} class="text-text-tertiary flex-shrink-0" aria-hidden="true" />
        }
        <span class="text-sm font-semibold text-text-primary">
          L{rung.rung} — {rung.label}
        </span>
        {rung.inferred && (
          <span class="ml-1 text-[10px] font-semibold bg-accent-bg text-accent rounded px-1"
                aria-label="inferred">~</span>
        )}
      </div>

      <!-- Evidence strings (indented under icon+name) -->
      <ul class="pl-6 space-y-1">
        {rung.evidence.map((ev, i) => (
          <li key={i} class="text-xs text-text-secondary">{ev}</li>
        ))}
      </ul>

      <!-- Inferred-L5 callout (always visible when rung is L5 and has inferred:true) -->
      {rung.rung === 5 && rung.inferred && (
        <p class="mt-1 text-xs text-text-secondary pl-6">
          Inferred — not hard-verified. Based on CLAUDE.md freshness and backbone-doc presence.
        </p>
      )}
    </li>
  ))}
</ul>
```

**Section C — Next steps (only when `evalData.nextSteps.length > 0`):**
```
<div class="border-t border-border-subtle pt-4">
  <h3 class="text-sm font-semibold text-text-primary mb-2">Next steps</h3>
  <ul role="list" class="space-y-1">
    {evalData.nextSteps.map((step, i) => (
      <li key={i} class="flex gap-2 text-sm text-text-secondary">
        <span aria-hidden="true" class="text-text-tertiary flex-shrink-0">→</span>
        <span>{step}</span>
      </li>
    ))}
  </ul>
</div>
```

**Section D — No next steps (headline = L6):**
When `evalData.nextSteps.length === 0`:
```
<div class="border-t border-border-subtle pt-4">
  <p class="text-sm text-status-success font-semibold">
    Fully adaptive — all six rungs complete.
  </p>
</div>
```

### 4. Degraded Row Treatment

When `eval` is absent from `CoverageRow` (scanner threw — `lvS.status === 'rejected'`), the `LevelBadgeCell` renders `—` (`text-text-tertiary text-xs`). The badge button is NOT rendered. No click handler. No drawer.

The row itself does NOT show any additional inline error text for the level column — the `—` is the entire signal. The existing row `degraded` field (which populates a global row-level degraded indicator if present) may surface a note in the row's existing degraded treatment, but `LevelBadgeCell` does not own that concern.

**Executor note:** The degraded cell appearance MUST look identical to the `understand` column's `—` fallback — not like a crashed cell, not like an error state.

## State Machine

The badge cell has exactly 5 render states:

| State | Condition | Render |
|-------|-----------|--------|
| L0 | `evalData.level === 0` | `L0` pill in `text-tertiary` tones (muted); button enabled |
| L1–L4 | `evalData.level` 1–4 | Level pill in amber (L1–L2) or blue (L3–L4); button enabled |
| L5–L6 | `evalData.level` 5–6 | Level pill in green; button enabled |
| Inferred | `evalData.inferred === true` | As above + `~` sigil appended; button enabled |
| Degraded | `evalData === undefined` | `—` text; NO button (no interaction) |

The drawer has exactly 2 render states: closed (not in DOM or `display:none`) and open (`showModal()`).
